## 一、阶段目标

### 1.1 用户结果

学员输入文字或确认后的 OCR 题目时，系统优先命中标准题，并展示不可变标准答案、教学解释、题库来源和版本；没有可靠证据或出现冲突时不猜，允许提交给校长。

### 1.2 业务结果

- 一批可信来源科目一题库能被结构化、机器校验、版本化和检索。
- 标准题不需要逐题人工审核。
- 异常题目与正常题目分流。
- 模型、Prompt、题库与检索配置的组合可被固定评测。
- 题库版本发布失败时不影响上一生效版本。

### 1.3 阶段完成定义

以下纵向链路在真实后端和真实 Embedding/Rerank 模型下成立，才算完成：

```text
受控测试题库
→ 导入并生成版本
→ 自动校验
→ 构建关键词与向量索引
→ 运行固定评测
→ 版本生效
→ 学员输入原题/改写题/OCR题
→ 精确或混合检索
→ 标准答案一致性校验
→ 展示来源与版本
→ 无证据/冲突安全降级
```

## 三、技术适配摘要

### 3.1 继续使用

- Next.js + React 学员端和校长端；
- FastAPI `/api/v1`；
- SQLAlchemy + Alembic；
- SQLite 本地业务事实源；
- HttpOnly Cookie 与现有 BFF；
- pytest、Vitest、Playwright；
- 现有 OCR、Answer、Evidence、ReviewTicket 与 AITrace。

### 3.2 新增依赖

| 依赖 | 用途 | 约束 |
|---|---|---|
| `chromadb` | 本地向量索引 | 锁定兼容版本；单进程写；数据可重建 |
| `openai` 或现有 `httpx` 兼容调用 | 百炼 Embedding | 优先复用现有 HTTP 封装，避免重复 SDK |
| Python 标准库 `csv` | CSV 导入 | 不为简单导入增加 DataFrame 依赖 |

是否实际增加 `openai` 依赖以开发时验证为准；若 `httpx` 已能稳定覆盖接口，不新增 SDK。

### 3.3 不采用

- LangChain/LlamaIndex；
- 独立 Elasticsearch/OpenSearch；
- 独立 Redis/Celery；
- 托管知识库作为唯一存储；
- 当前阶段 PostgreSQL/pgvector 迁移。

唯一约束：`knowledge_version_id + external_id`；同时对题干与选项指纹建立索引。

### 6.4 KnowledgeChunk

标准题不按任意字数切片。每题形成稳定的检索文档：

```text
题干 + 有序选项 + 标准答案语义描述 + 解析 + 知识点
```

| 字段 | 说明 |
|---|---|
| id | 稳定 chunk ID |
| question_id/version_id | 反向关联 |
| content | 用于关键词/向量检索的文本 |
| content_hash | 幂等与变化检测 |
| embedding_status | PENDING/READY/FAILED |
| vector_record_id | Chroma 记录 ID |

Chroma metadata 只保存可过滤的非敏感字段：`school_id`、`version_id`、`region`、`license_type`、`question_type`、`status`。

### 6.5 KnowledgeValidationIssue

| 字段 | 说明 |
|---|---|
| issue_type | MISSING_FIELD/DUPLICATE/ANSWER_CONFLICT/VERSION_CONFLICT/INVALID_OPTION/ENCODING_ERROR 等 |
| severity | P0/P1/P2 |
| row_number/external_id | 原始定位 |
| safe_message | 管理端说明 |
| status | OPEN/RESOLVED/IGNORED |
| resolution | 处置结论 |

### 6.6 RetrievalTrace

记录：query hash、规范化文本、范围过滤、精确命中、关键词候选、向量候选、融合排名、Rerank 排名、最终证据、模型与知识版本、各阶段耗时、错误码。不记录无必要的完整学生身份。

### 6.7 EvaluationDataset / EvaluationCase / EvaluationRun

- Dataset：名称、版本、来源、状态；
- Case：输入题目、期望题目 ID、期望答案、范围、错误级别；
- Run：数据集版本、知识版本、Embedding/Rerank/Prompt/工作流版本、指标和门禁结果；
- CaseResult：召回、答案、证据、错误标签和 Trace。

## 七、导入与机器校验

### 7.1 输入 Schema V1

必填：`external_id`、`stem`、`question_type`、`options`、`standard_answer`、`explanation`。可选：`knowledge_points`、`region`、`license_type`、`effective_from`、`image_ref`。

### 7.2 规范化

- Unicode NFKC；
- 统一全半角和空白；
- 统一选项标签；
- 保留否定词、数字、单位、标志描述和语序；
- 不做会改变语义的同义词替换；
- 规范化规则必须版本化。

### 7.3 机器校验顺序

1. 文件与 Schema 校验；
2. 必填字段和长度；
3. 题型与选项数量；
4. 标准答案是否指向合法选项；
5. 同 externalId 重复；
6. 同题干+选项不同答案冲突；
7. 新旧版本差异；
8. 地区/车型/生效时间；
9. 内容哈希与重复导入；
10. 生成 chunk；
11. Embedding；
12. 索引完整性抽查；
13. 固定评测；
14. 门禁通过后激活。

P0 问题阻断整个版本；P1 默认阻断对应题目并允许其他有效题进入候选版本；是否允许部分版本激活在正式题库到达后再次确认。MVP 默认整批阻断，降低版本混合风险。

## 八、检索与回答流程

### 8.1 查询预处理

- 使用已确认 OCR 文本或学员文本；
- 提取题干和选项；
- 继承学员 session 的地区与车型；
- 生成规范化文本和指纹；
- 不让生成模型自由改写标准题查询。

### 8.2 多路召回

```text
A. 题干+选项精确指纹
B. 仅题干精确指纹
C. FTS5 关键词 Top 20
D. Chroma 向量 Top 20
```

所有候选必须先过滤：`school_id + ACTIVE version + region + license_type + VALID status`。

### 8.3 融合与重排

- 精确题干+选项命中直接进入最高优先级；
- 关键词和向量候选用 RRF 合并；
- 同 questionId 去重；
- 最多 30 条传入 `qwen3-rerank`；
- 最多 5 条进入最终证据；
- Rerank 失败时可使用 RRF 排名，但必须记录降级；
- 分数阈值通过固定评测确定，不在开发时凭感觉写死。

### 8.4 标准答案阻断

- Top 候选答案一致且命中门槛：返回标准答案；
- 精确命中：标准答案完全由题库返回；
- 高排名候选答案冲突：`KNOWLEDGE_CONFLICT`，不生成确定答案；
- 无候选或低于门槛：`NO_TRUSTED_EVIDENCE`；
- 版本/范围不匹配：`KNOWLEDGE_SCOPE_MISMATCH`；
- 模型解释与标准答案不一致：`ANSWER_CONSISTENCY_FAILED`。

上述阻断均可创建校长工单。

### 8.5 教学解释 Prompt V2

输入：

- 原始问题；
- 标准题 ID；
- 不可变标准答案；
- 最多 5 条证据；
- 地区、车型和知识版本；
- 首次/二次解释模式。

输出结构：

```json
{
  "direct_answer": "必须与标准答案一致",
  "short_reason": "简短原因",
  "detail": "教学解释",
  "common_mistake": "易错提醒",
  "cited_evidence_ids": ["..."],
  "route": "standard_exact|standard_hybrid|knowledge_only"
}
```

后置校验失败时不展示草稿。

## 十四、风险与处理

| 风险 | 处理 |
|---|---|

| 新版本发布破坏线上 | 评测门禁、原子激活、保留旧版本和回退 |
