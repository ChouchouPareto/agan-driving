# 驾校科目一智能助教：模拟需求评审 v0.1

## 评审结论

产品定位、MVP范围、核心旅程、AI链路、质量门槛和试点方案已基本明确。当前PRD可以进入最后补全，但尚不能直接标记为最终研发版。

## 一、阻断研发或试点的问题

### 1. Web身份与邀请码规则未落细

- 邀请码是一人一码还是多人共用；
- 是否绑定手机号；
- 学员更换设备后如何恢复记录；
- 试点结束后账号如何失效；
- 数据删除申请如何验证本人。

影响：前端登录、账号表、学习记忆、权限与测试用例无法完全确定。

### 2. 种子题库的首版覆盖范围未确定

- 首版需要整理多少道题；
- 高风险法规与高频知识点覆盖范围；
- 供应商资料预计何时到位；
- 谁对种子题库作最终专业确认。

影响：无法冻结评测集，也无法判断上线门槛是否可达。

### 3. 教练审核排班责任未落地

- 谁担任值班审核角色；
- 工作时间的具体定义；
- 无人响应时谁作为后备；
- P0问题由谁决定暂停和恢复。

影响：异常闭环虽然有产品流程，但真实试点无法执行。

### 4. AI与数据部署方案未完成技术评审

- Dify云端或自托管；
- 业务数据库、对象存储、日志位置；
- 模型API密钥和权限管理；
- 图片、对话和审核数据的删除任务；
- 故障、限流与模型切换策略。

影响：后端架构、成本、安全和运维责任无法冻结。

## 二、开发前建议补齐

### 产品与设计

- 页面清单、页面状态和导航关系；
- OCR识别结果的校正界面；
- 回答异议、教练处理和结果回传的状态文案；
- Web内提醒的入口、未读状态和关闭入口；
- 空状态、网络错误、模型超时和上传失败状态。

### AI与RAG

- 标准题精确匹配、高可信匹配和无法匹配的阈值规则；
- 题库、法规和教学解析的元数据字段；
- Prompt输入输出JSON结构；
- 机器复核与人工预警的判定组合；
- 评测样本分类、评分表和错误归因编码。

### 后端与数据

- 学员、会话、题目、知识点、提醒、审核工单的状态模型；
- 图片7天、对话180天、试点后30天学习记忆的定时删除机制；
- 操作审计、回答链路版本和数据导出；
- 看板计算周期和数据延迟说明。

### 测试

- 标准题、开放问答、口语化、歧义、缺失信息、错误OCR和新规样本；
- P0/P1/P2问题的复现、修复和回归流程；
- 数据隔离、越权访问和删除验证；
- 模型超时、RAG无召回、审核超时等降级测试。

## 三、可以后续补充

- ERP/SaaS的具体厂商适配协议；
- 多驾校完整租户与商业计费；
- 科目二、三、四的详细功能；
- 外部微信通知与更复杂的主动学习计划；
- OpenAI等外部模型的长期基准评测方案。

## 四、建议的最后补全顺序

```text
确认Web身份和题库首版范围
→ 确认教练审核责任
→ 技术评审Dify与数据部署
→ 补页面与状态说明
→ 补数据模型和AI输入输出规则
→ 形成评测集与验收用例
→ 再进行最终PRD评审
```
