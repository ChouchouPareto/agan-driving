## 1. 阶段定义

V2.0 第一阶段对应 PRD 的 2B：OCR 可信输入闭环。

阶段目标：学员能在现有 Web 中安全上传一道科目一题目图片，系统通过 qwen-vl-ocr 得到结构化题干和选项；不确定字段由学员确认；确认后的内容进入现有标准题/问答流程。刷新、断网、重复提交或 OCR 失败时，任务可查询、可恢复、可审计。

本阶段不是建设完整图片聊天，也不是建设校长后台、知识平台或学习进度系统。

## 2. 成功定义

当以下链路在真实浏览器、真实后端和真实 OCR 模型下成立，才算本阶段完成：

    邀请码进入
      → 选择或拍摄一张题目图片
      → 服务端安全校验并私有保存
      → 创建可恢复的 OCR 任务
      → 展示识别结果与低置信字段
      → 学员修正并确认
      → 幂等创建正式 Question
      → 标准题命中后展示可靠回答
         或无可靠证据时安全降级
      → 刷新后仍能恢复当前状态

## 5. 用户故事

### US-01 上传题目

作为科目一学员，我可以选择或拍摄一道题目图片，并在上传前知道格式、大小和失败原因。

### US-02 查看处理状态

作为学员，我可以看到“上传中、排队中、识别中、待确认、完成、失败”等真实状态，不看到虚构百分比。

### US-03 校正确认

作为学员，我可以查看识别出的题干和选项，修改系统标出的不确定字段，然后确认。

### US-04 继续问答

作为学员，我确认 OCR 后，系统会用确认后的内容创建正式问题，并沿用现有可信回答或转人工逻辑。

### US-05 恢复任务

作为学员，我刷新、断网重连或稍后返回时，可以继续当前 OCR 任务，不会重复扣费或创建重复问题。

### US-06 数据安全

作为学员，我只能查看自己的图片和 OCR 结果，原图会按约定时间删除。

## 6. 页面和交互

### 6.1 /ask

新增：

- “上传题目截图/拍照”入口；
- 格式和大小说明；
- 图片本地预览与移除；
- 上传和 OCR 状态卡；
- 失败后的重新上传或改用文字输入；
- questionId、ocrTaskId 通过 URL 恢复。

保留：

- 文字输入；
- 现有回答卡和反馈；
- “不懂就问校长”；
- Loom 紫色、中性浅色、圆角卡片和移动优先布局。

### 6.2 OCR 确认面板

桌面可使用右侧面板，移动端使用页面内卡片或底部面板。必须包含：

- 缩略图；
- 题干输入框；
- A/B/C/D 等选项输入框；
- 不确定字段的文字和图标提示；
- “确认并提问”主操作；
- “重新识别”“重新上传”“改用文字输入”次操作。

交互规则：

- 低置信状态不能只用颜色表示；
- 提交失败保留全部修正；
- 提交中禁用重复点击；
- 键盘可完成全部操作；
- 关闭面板前提示未保存修改；
- 减少动态效果模式不影响使用。

### 6.3 任务恢复

- /ask?ocrTaskId=... 恢复 OCR；
- /ask?questionId=... 继续复用现有问题恢复；
- URL 中同时存在二者时，以后端关联关系为准；
- 资源不存在、过期或越权时显示安全错误并清理无效参数；
- 不使用 Local Storage 保存 Bearer Token 或 OCR 原文。

## 10. API 契约草案

### 10.1 上传图片

POST /api/v1/assets/images

输入：multipart/form-data，字段 image。

成功输出：

    {
      "asset_id": "uuid",
      "status": "READY",
      "mime": "image/jpeg",
      "size_bytes": 123456,
      "expires_at": "ISO-8601",
      "request_id": "uuid"
    }

错误：UNSUPPORTED_IMAGE_TYPE、IMAGE_TOO_LARGE、IMAGE_DECODE_FAILED、UNSAFE_IMAGE、UNAUTHORIZED。

### 10.2 创建 OCR 任务

POST /api/v1/ocr-tasks

请求头：Idempotency-Key。

输入：

    {
      "asset_id": "uuid"
    }

输出：

    {
      "id": "uuid",
      "status": "QUEUED",
      "request_id": "uuid"
    }

### 10.3 查询 OCR 任务

GET /api/v1/ocr-tasks/{id}

输出包含：

- id、status、request_id；
- asset 的短期预览引用；
- field 列表；
- needs_confirmation；
- safe_error；
- linked_question_id；
- created_at、updated_at。

### 10.4 修正字段

PATCH /api/v1/ocr-tasks/{id}/fields

输入：

    {
      "version": 2,
      "fields": [
        {
          "field_id": "uuid",
          "value": "修正后的内容"
        }
      ]
    }

要求：乐观锁、所有权校验、保留原值和审计。

### 10.5 确认并提问

POST /api/v1/ocr-tasks/{id}/confirm

请求头：Idempotency-Key。

输出：

    {
      "ocr_task_id": "uuid",
      "question_id": "uuid",
      "status": "QUESTION_CREATED"
    }

重复提交返回同一 question_id。

## 11. OCR Schema

标准化字段：

    {
      "schema_version": "1.0",
      "question_type": "single_choice|multiple_choice|true_false|unknown",
      "stem": {
        "value": "题干",
        "confidence": 0.0,
        "needs_confirmation": true
      },
      "options": [
        {
          "label": "A",
          "value": "选项内容",
          "confidence": 0.0,
          "needs_confirmation": false
        }
      ],
      "warnings": []
    }

规则：

- 供应商原始格式先在 Adapter 内归一化；
- 缺题干、选项重复、标签异常和结构不完整进入 WAITING_USER；
- 置信阈值配置化并带版本；
- 前端不根据单个模型分数自行判定是否可信；
- 不要求 OCR 模型输出正确答案。

## 12. Worker 与恢复

### 12.1 任务领取

- Worker 原子领取 QUEUED 任务；
- 写 started_at 和 attempt_count；
- 同一任务只能被一个 Worker 有效处理；
- 进程崩溃后，超时 PROCESSING 可按规则重新入队。

### 12.2 重试

- 网络超时、限流和临时供应商错误可重试；
- Schema 不合法可进行一次受控修复或直接失败；
- 不可解码图片和业务校验失败不重试；
- 最大次数配置化；
- 每次尝试记录错误类别，不记录密钥和原始 base64。

### 12.3 一致性

- OCR 完成和字段写入在事务中提交；
- confirm 使用任务版本和幂等键；
- Question 创建成功后再写 linked_question_id；
- 中途失败可重新查询，不留下“已成功但找不到问题”的状态。

## 13. 文件生命周期

1. 上传完成后状态 READY；
2. OCR 处理中保持私有；
3. 仅本人通过受权端点查看短期预览；
4. 默认 expires_at 为上传后 7 天；
5. 清理 Worker 删除物理文件并写删除结果；
6. 数据库保留最小元数据和审计，不保留公开路径；
7. 删除失败进入可重试状态和告警；
8. 测试验证文件确实不可再次访问，而不只验证数据库标记。

## 14. 安全要求

- BFF 和 FastAPI 均限制请求体；
- 后端检查魔数、MIME、尺寸和可解码性；
- 设置像素数量上限，防止解压炸弹；
- 文件名随机化并禁止路径穿越；
- 图片不经过静态公开目录；
- asset、task、field 和 question 均校验 student 所有权；
- OCR 供应商 Key 只在后端环境；
- 异常响应不返回堆栈、文件系统路径和供应商原始错误；
- 图片下载设置安全 Content-Type 和 Content-Disposition；
- 日志与监控不采集原图或完整 OCR 文本。

## 15. 前端任务状态

| 后端状态 | 前端状态 | 文案 |
|---|---|---|
| 未选择 | idle | 上传题目截图 |
| 上传中 | submitting | 正在安全上传 |
| QUEUED | queued | 已进入识别队列 |
| PROCESSING | running | 正在识别题目 |
| WAITING_USER | waiting_user | 请确认识别内容 |
| CONFIRMED/QUESTION_CREATED | succeeded | 已确认，正在进入答疑 |
| FAILED | failed | 识别失败，可重试或文字输入 |
| 网络中断 | disconnected | 任务可能仍在运行，正在恢复 |
| 未知状态 | stale | 状态待确认，正在重新获取 |
| EXPIRED | failed | 图片已过期，请重新上传 |

不展示模型推测的进度百分比。

## 17. 测试计划

### 17.1 后端单元/集成

- 合法 JPEG/PNG/WebP；
- 扩展名与真实 MIME 不一致；
- 超过大小或像素限制；
- 损坏图片、SVG 和非图片；
- 路径穿越文件名；
- 他人 asset/task/field 越权；
- 重复创建 OCR 任务；
- Worker 并发领取；
- 超时任务恢复；
- Provider 超时、限流、错误和非法 Schema；
- 低置信字段必须确认；
- 版本冲突；
- 重复 confirm 返回同一问题；
- 过期和物理删除；
- 数据库重启恢复。

### 17.2 前端

- 上传前校验；
- 失败后保留可恢复信息；
- 所有任务状态映射；
- OCR Schema 异常兜底；
- 字段修正和提交中保护；
- URL 恢复；
- 未知状态不当作成功；
- 键盘、焦点、ARIA 和错误播报。

### 17.3 Playwright

1. 邀请进入 → 上传清晰截图 → 确认 → 获得标准题答案；
2. 低置信 OCR → 修正字段 → 确认 → 刷新恢复；
3. OCR 失败 → 重新上传或文字输入；
4. 断网后恢复 → 不重复创建任务；
5. 越权/过期资源 → 安全错误且无内容泄露。

### 17.4 真实 OCR 样本

至少包括：

- 清晰应用截图；
- 手机拍摄且轻微透视；
- 低光、反光或轻微模糊；
- 选项换行/长文本；
- 无关图片或非题目图片。

每个样本记录题干完整率、选项完整率、人工修正字段数、耗时、重试和费用。

## 18. 验收门槛

### 功能

- 合法图片可完成上传、识别、确认和提问；
- 低置信字段一定经过用户确认；
- 确认后复用现有标准题/问答逻辑；
- 无证据时不输出伪确定答案。

### 可靠性

- 刷新和断网后可恢复；
- 重复提交不产生重复 OCR 费用或 Question；
- Worker 重启后任务可继续；
- 删除任务可以验证真实文件已删除。

### 安全

- 越权测试全部通过；
- 密钥、原图、base64 和绝对路径不进入日志；
- 伪造图片和超限请求被服务端拒绝；
- 私有图片没有永久公开 URL。

### 工程质量

- pytest 通过；
- npm run lint 通过；
- npm run typecheck 通过；
- npm run test 通过；
- npm run build 通过；
- Playwright 核心链路通过；
- Alembic 新库升级和回退验证通过。

### 真实性

- 使用真实 qwen-vl-ocr 完成规定样本；
- 明确记录模型 ID、调用时间、延迟、错误和成本；
- mock、截图或静态演示不能替代真实验收。

## 20. 风险与回退

| 风险 | 降级/回退 |
|---|---|
| qwen-vl-ocr 不可用 | 保留文字提问；任务失败可重试 |
| OCR 结果不稳定 | 强制确认；不直接进入标准题 |
| Worker 恢复复杂 | 先单 Worker + 持久化领取，不回退到请求内长阻塞 |
| 本地文件方案不适合试点 | 通过 Storage Adapter 换对象存储 |
| 2A 回归 | 回退到 29ae01b 或第一阶段归档 f4b675e |
| 范围膨胀 | 保留 2B；校长后台、知识和学习证据继续后移 |
| 未确认隐私规则 | 只做本地开发，不进入真实学员试点 |

回退不得删除用户数据或覆盖已有未提交文件。
