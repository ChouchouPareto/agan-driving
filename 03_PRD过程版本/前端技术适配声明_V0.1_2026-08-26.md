| 项目 | 结论 |

| 产品类型 | 驾校交付给学员的B2B2C科目一AI答疑产品 |
| 主要用户 | 科目一学员、值班教练/校长、项目运营 |
| 主要终端 | 学员侧移动Web优先；教练/运营侧桌面Web优先 |
| 项目状态 | 已有第一阶段可运行代码，不是新建空项目 |
| 第二阶段目标 | 增加截图/OCR校正、完整校长工作台、题库维护与评测入口，同时修复第一阶段前端工程基础缺口 |

第二阶段不是“把页面做得更多”，而是让两条真实闭环成立：

```text
学员截图提问
→ OCR识别与人工校正
→ 可信问答或转校长

异常工单进入教练工作台
→ 教练核查、回复、关闭
→ 学员看到真实处理结果
→ 可复用结论进入待审核知识流程
```

## 3. 当前前端基线

### 已具备

- Next.js 16.3.3；
- React 19.2；
- TypeScript strict；
- ESLint、类型检查和生产构建；
- Fetch Streaming读取SSE；
- Loom紫色语义变量和响应式基础；
- 第一阶段邀请码、提问、回答、反馈和工单状态；
- 生产依赖安全审计0个已知漏洞（第一阶段归档时）。

### 必须修正

1. `page.tsx`同时承担页面、鉴权、API、流解析和全部业务状态；
2. 普通请求和流式请求直接散落在页面；
3. 后端返回值没有运行时校验；
4. 长期访问令牌保存在Local Storage；
5. 页面状态无法通过URL恢复；
6. 刷新后conversation/question/ticket上下文丢失；
7. 提交没有幂等键，快速重复操作存在重复请求风险；
8. 没有前端单元、组件和E2E测试；
9. 当前实际没有安装Tailwind，与早期技术文档描述不一致；
10. 浏览器真实验收尚未形成可重复流程。

## 4. 第二阶段技术选择

### 4.1 框架与版本

- 延续Next.js 16.3.3、React 19、TypeScript strict；
- 不跨大版本升级；
- 安全修复允许在同一大版本内升级，升级后重新执行完整测试；
- 使用App Router，将静态布局与交互区域分开，不继续把全站写成单个Client Component。

### 4.2 样式与组件

推荐：

- 保留当前CSS语义变量；
- 新增CSS Modules组织页面与组件样式；
- 使用Radix UI基础组件实现Dialog、Drawer、Tabs、Dropdown等复杂无障碍交互；
- 使用Lucide统一图标；
- 不在第二阶段引入完整视觉组件库；
- 不把现有样式一次性迁移到Tailwind。

理由：当前产品已经有明确Loom Token且第一阶段使用普通CSS。第二阶段同时引入OCR、后台和测试，若再全量迁移Tailwind会扩大回归面，但不会直接提升核心闭环质量。

### 4.3 API与运行时校验

建立统一层级：

```text
页面/业务组件
→ Feature Hook
→ Feature API
→ 统一HTTP/Stream Client
→ Next.js同源代理
→ FastAPI
```

- API地址只在统一客户端配置；
- 请求ID、错误、鉴权和超时集中处理；
- 使用Zod校验关键API返回；
- 后端未知枚举映射为安全的`unknown`状态，不静默当作成功；
- SSE解析器独立为纯函数并测试；
- 普通请求与流式请求共享同一个同源路径策略。

### 4.4 鉴权

第二阶段迁移为：

- Next.js Route Handler/BFF代理；
- 服务端设置HttpOnly、SameSite Cookie；
- 浏览器不再读取Bearer Token；
- BFF从Cookie读取会话并向FastAPI附加后端凭证；
- 前端只访问同源`/api/*`；
- 后端继续执行最终权限判断。

迁移完成后清理Local Storage中的旧`access_token`。迁移需兼容第一阶段邀请码流程，失败可回退到第一阶段存档分支。

### 4.5 服务端数据与客户端状态

引入TanStack Query，因为第二阶段出现多页面共享的工单、OCR任务、题库和评测状态，需要缓存、失效、重试和刷新恢复。

不引入Zustand。状态按四层管理：

| 状态 | 存放位置 |
|---|---|
| questionId、ticketId、后台筛选 | URL |
| OCR、问题、回答、工单、评测结果 | 后端＋TanStack Query |
| 输入框、抽屉、弹窗 | 组件局部状态 |
| 非关键展示偏好 | Local Storage或后端偏好接口 |

### 4.6 表单

- 简单提问继续使用原生受控表单；
- OCR多字段校正、题库编辑和教练回复采用React Hook Form＋Zod；
- 提交失败保留输入；
- 提交中禁用重复操作；
- 创建问题、工单、发布和评测运行需要幂等键。

### 4.7 流式与任务恢复

- 继续使用Fetch Streaming，不使用EventSource；
- 原因：当前需要鉴权和受控请求头/BFF；
- 前端统一映射`idle/submitting/queued/running/streaming/waiting_user/succeeded/failed/disconnected/stale`；
- 断线时先按questionId或ocrTaskId查询后端状态，再决定是否恢复流；
- 页面卸载时取消浏览器请求，但不把它描述为取消后端任务；
- `chunk`只用于临时展示，`done`后的后端结果才是正式事实。

### 4.8 测试

- Vitest：状态映射、SSE解析、错误归一化和Schema；
- React Testing Library：邀请、OCR校正、工单操作、加载/失败/恢复；
- MSW：组件和集成测试中的可控接口；
- Playwright：学员OCR闭环与校长工单闭环；
- 真实浏览器人工验收：390、768、1280、1440px；
- 每次交付执行lint、typecheck、test、build和生产依赖审计。

## 5. 前端统一任务状态

| 后端状态 | 前端状态 | 学员/教练看到的内容 |
|---|---|---|
| 未提交 | `idle` | 可以输入或上传 |
| 正在创建 | `submitting` | 正在提交，按钮不可重复点击 |
| `SUBMITTED/QUEUED` | `queued` | 已受理，等待处理 |
| `ROUTING/RETRIEVING/GENERATING/VALIDATING/PROCESSING` | `running/streaming` | 显示真实阶段，不虚构百分比 |
| OCR需要校正 | `waiting_user` | 明确标出低置信字段并要求确认 |
| `ANSWERED/REPLIED/CLOSED` | `succeeded` | 展示后端正式结果 |
| `NEEDS_REVIEW` | `queued` | 已转校长，不展示不可靠答案为最终结论 |
| `REFUSED` | `failed`或安全结束 | 解释范围与下一步 |
| `FAILED` | `failed` | 保留输入，提供重试或转人工 |
| 网络中断 | `disconnected` | 说明任务可能仍运行，开始恢复 |
| 未知枚举 | `stale` | 重新查询并显示安全提示 |

## 6. 页面与路由

### 学员端

- `/enter`：邀请码进入；
- `/ask`：文字/截图提问；
- `/questions/[questionId]`：问题、OCR、回答和反馈；
- `/tickets/[ticketId]`：校长工单时间线与回复。

### 教练/运营端

- `/admin/tickets`：工单队列；
- `/admin/tickets/[ticketId]`：核查、回复与状态处理；
- `/admin/knowledge/questions`：题库列表与编辑；
- `/admin/evaluations`：评测运行与失败样本。

第二阶段不创建学习页、提醒页、驾校经营看板和多租户设置页。

## 7. 核心产物

- OCR结构化结果：题干、选项、低置信字段、原图引用；
- 正式回答：标准答案、解释、易错点和依据；
- 校长工单：状态、风险原因、回复、时间线和审计信息；
- 题库记录：来源、版本、地区/车型、审核状态；
- 评测运行：状态、指标、失败样本和错误归因。

## 8. 响应式目标

- 学员端：390px移动端可完成上传、校正、提问和查看回复；
- 教练端：1280/1440px使用232px侧栏和列表＋详情；
- 768px后台改为单列或抽屉详情；
- 所有触控目标不小于44×44px；
- OCR校正桌面用右侧抽屉，移动端用底部面板；
- 不出现无意横向滚动；
- 动画遵守Loom参数与`prefers-reduced-motion`。

## 9. 与前端手册的偏离

| 偏离 | 原因 | 影响 |
|---|---|---|
| 第二阶段不引入Tailwind | 现有项目已用语义CSS，避免同时迁移样式和新增核心闭环 | 使用CSS Modules维持组织性；后续单独评估 |
| 不立即生成OpenAPI客户端 | 后端第二阶段契约尚需先补齐 | 先用Zod＋手写Feature API，契约稳定后生成 |
| 不把全部状态交给TanStack Query | 输入与抽屉等仍是局部UI状态 | 避免全局状态过度复杂 |
| 暂不引入Sentry和产品分析 | 尚未进入真实用户测试且埋点方案未冻结 | 真实试点前补充 |

## 10. 后端前置依赖

第二阶段前端不能凭空模拟为“已完成”，需要后端提供：

- 管理员/值班教练身份和权限；
- 图片上传与安全校验；
- OCR任务创建、状态、结果和字段校正；
- 问题幂等提交和状态查询；
- 工单列表、详情、接单、回复、关闭和审计；
- 题库列表、详情、编辑、审核、发布/下线；
- 评测运行、状态、结果和失败样本；
- 统一错误、requestId和未知状态兼容；
- Cookie/BFF所需的安全会话交换方式。

接口未实现前可以使用MSW推进组件测试，但不得把MSW结果当作真实联调完成。

## 11. 开发前待确认

以下问题会改变第二阶段范围或安全方案：

1. 第二阶段是否确认同时包含三块：OCR、完整校长工作台、题库维护与评测入口；
2. 教练/运营测试身份采用独立管理员邀请码，还是预设测试账号；

4. 题库维护第二阶段做到单条编辑，还是同时包含CSV批量导入；
5. 评测中心只运行预置评测集，还是允许上传评测文件。
