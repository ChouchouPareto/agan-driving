## 1. 阶段目标

第二阶段让产品从“文字问答演示”前进到两条可真实操作的质量闭环：

1. 学员上传题目截图，校正OCR结果后获得可信回答；
2. 校长在工作台接收异常工单，核查依据、回复学员，并把可复用结论送入知识审核流程。

同时建立最小题库维护和评测入口，使错误能够被发现、归因、修正和回归验证。

## 4. 用户流程

### 4.1 学员截图提问

```text
进入问一问
→ 选择图片或拍照
→ 前端检查格式/大小
→ 上传并创建OCR任务
→ 显示识别进度
→ 展示原图、题干、选项和低置信字段
→ 学员校正并确认
→ 以确认后的文本创建问题
→ 标准题/RAG处理
→ 展示正式回答或转校长
```

### 4.2 校长处理

```text
异常创建工单
→ 工单进入队列
→ 值班人员查看详情
→ 接单并进入处理中
→ 核对原图、OCR、答案、依据和风险
→ 填写处理结论
→ 回复学员
→ 学员查看
→ 关闭工单
→ 可复用结论进入知识待审核区
```

### 4.3 知识修正与回归

```text
从失败样本/工单定位知识问题
→ 编辑题库或解析
→ 专业审核
→ 发布新版本/下线旧版本
→ 运行预置评测集
→ 查看失败样本与错误归因
→ 达标后保留发布版本
```

## 5. 角色与权限

| 角色 | 权限 |
|---|---|
| 学员 | 访问自己的图片、问题、回答和工单 |
| 值班教练 | 查看分配/可领取工单，处理和回复，不直接发布题库 |
| 知识管理员 | 编辑知识、提交审核、运行评测 |
| 专业审核员 | 审核、发布、下线和恢复知识版本 |
| 项目运营 | 查看必要工单和评测信息，不查看无关学员数据 |

前端隐藏按钮不是权限控制，所有权限由后端再次校验。

## 6. 页面与状态矩阵

| 页面/模块 | 初始/空 | 加载/运行 | 等待用户 | 成功 | 失败/恢复 |
|---|---|---|---|---|---|
| `/ask` | 文字/拍照入口 | 上传进度 | 等待选择图片 | 创建OCR任务 | 保留输入，可重试 |
| OCR校正 | 无任务不展示 | 识别中 | 校正低置信字段 | 确认并提问 | 重新识别/文字输入 |
| 问题详情 | 加载骨架 | 检索/生成/检查 | 需要补充 | 正式回答 | 查询状态后恢复 |
| 学员工单 | 无工单 | 刷新状态 | 等待校长 | 回复/关闭 | 断线后重新获取 |
| 工单队列 | 空队列 | 加载/筛选 | — | 列表展示 | 重试，不显示假空态 |
| 工单详情 | 无选择 | 接单/提交回复 | 需要补充资料 | 回复成功 | 保留回复草稿 |
| 题库列表 | 无记录 | 搜索/分页 | — | 结果列表 | 错误与重试 |
| 题库编辑 | 新建/编辑 | 保存中 | 审核确认 | 保存/发布 | 保留表单、版本冲突提示 |
| 评测中心 | 无运行 | queued/running | — | 指标和失败样本 | 可重试、保留历史 |

## 7. Agent与任务状态

统一前端状态：

```text
idle → submitting → queued → running/streaming
→ waiting_user → succeeded

异常：failed / disconnected / stale / cancelled
```

规则：

- OCR进度和AI回答进度不展示虚构百分比；
- 等待OCR校正属于`waiting_user`，不是失败；
- 浏览器请求取消不等于后端任务取消；
- 断线后先查询任务状态，不重复创建；
- 后端未知状态进入`stale`并重新获取；
- 只有后端`done`/正式记录才能展示为最终结果；
- 创建类请求使用幂等键。

## 8. 数据模型增量

### 图片与OCR

- `uploaded_assets`：文件名、受控路径、MIME、大小、hash、所属学员、状态、过期时间；
- `ocr_tasks`：asset_id、student_id、status、provider、model_id、raw_result、error_code；
- `ocr_fields`：task_id、field_type、value、confidence、needs_confirmation、corrected_value；
- `ocr_audit_logs`：原值、校正值、操作者、时间。

### 工单处理

- `review_ticket_assignments`：工单、处理人、接单时间；
- `review_ticket_messages`：发送者、内容、可见范围、时间；
- `review_ticket_events`：状态变化、理由、操作者；

### 知识与评测

- `question_bank_items`：题干、选项、标准答案、解析、来源、版本、地区、车型、状态；
- `knowledge_revisions`：变更前后、提交人、审核人、审核状态；
- `evaluation_runs`：评测集版本、状态、开始/结束、模型/Workflow/Prompt版本；
- `evaluation_results`：样本、期望、实际、得分、错误归因。

图片二进制不存入关系数据库，只保存元数据和受控引用。

## 9. API契约草案

### 学员与OCR

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/v1/assets/images` | 上传图片，校验真实MIME、大小和文件名 |
| `POST` | `/api/v1/ocr-tasks` | 创建OCR任务，要求幂等键 |
| `GET` | `/api/v1/ocr-tasks/{id}` | 查询真实状态和字段 |
| `PATCH` | `/api/v1/ocr-tasks/{id}/fields` | 提交字段校正 |
| `POST` | `/api/v1/ocr-tasks/{id}/confirm` | 确认并创建问题 |
| `GET` | `/api/v1/questions/{id}` | 恢复问题、回答与状态 |

### 工单后台

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/v1/admin/review-tickets` | 队列、筛选、分页 |
| `GET` | `/api/v1/admin/review-tickets/{id}` | 详情、证据、审计 |
| `POST` | `/api/v1/admin/review-tickets/{id}/claim` | 接单，幂等且防并发 |
| `POST` | `/api/v1/admin/review-tickets/{id}/reply` | 回复学员 |
| `POST` | `/api/v1/admin/review-tickets/{id}/close` | 关闭，需权限和理由 |

### 题库与评测

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/v1/admin/question-bank` | 查询题库 |
| `GET` | `/api/v1/admin/question-bank/{id}` | 记录与版本 |
| `POST/PATCH` | `/api/v1/admin/question-bank` | 新建或编辑草稿 |
| `POST` | `/api/v1/admin/question-bank/{id}/submit-review` | 提交审核 |
| `POST` | `/api/v1/admin/question-bank/{id}/publish` | 专业审核员发布 |
| `POST` | `/api/v1/admin/question-bank/{id}/deactivate` | 下线并记录理由 |
| `POST` | `/api/v1/admin/evaluation-runs` | 运行预置评测集，要求幂等键 |
| `GET` | `/api/v1/admin/evaluation-runs/{id}` | 运行状态、指标和失败样本 |

所有接口返回统一错误、requestId、明确枚举和权限要求。契约在编码前以OpenAPI或Schema冻结。

## 10. 图片与OCR规则

建议初始限制（待OCR服务确认后冻结）：

- 格式：JPEG、PNG、WebP；
- 单张上限：10MB；
- 每次1张；
- 前端扩展名检查只做即时反馈，后端验证真实MIME；
- 文件名服务端重命名，禁止使用用户路径；
- 原图默认7天删除；
- OCR低置信度字段必须人工确认；
- 识别失败可重新上传或改用文字输入；
- OCR确认后保存校正结果和审计记录；
- 原图引用不得是永久公开URL。

## 11. 工单业务规则

- 同一问题重复转人工返回原工单，不重复创建；
- 接单使用并发保护，不能两人同时占有；
- 回复提交中禁止重复操作；
- 学员只看用户可见消息，不暴露内部备注；
- `REPLIED`表示已回复等待学员查看；
- `CLOSED`需记录关闭原因；
- 人工修改答案不得直接发布到正式知识库；
- 可复用结论只能进入知识草稿/待审核状态；
- 所有状态变化写审计日志；
- 趣味文案只存在学员端，后台使用正式状态。

## 12. 题库与评测规则

- 标准答案与模型解释分离；
- 题库内容必须有来源、版本、地区/车型和审核状态；
- 未审核、冲突、过期内容不得进入确定性通道；
- 发布创建不可变版本，修改必须产生新修订；
- 下线不删除历史回答的审计关联；
- 评测集与生产知识隔离；
- 运行记录固定题库、Prompt、Workflow和模型版本；
- Reviewer模型只作辅助，专业审核是最终判断；
- P0失败阻止对应版本继续发布。

## 18. 风险与回退

| 风险 | 降级/回退 |
|---|---|
| OCR服务不可用 | 保留文字输入；OCR切片不宣称通过 |
| Cookie/BFF迁移失败 | 回退第一阶段存档，修复后重新迁移，不长期保留双鉴权 |
| 后台范围过大 | 先完成工单闭环，题库与评测推迟到2D |
| 题库权限未冻结 | 只允许草稿与审核，不开放发布 |
| 真实评测耗时 | 使用持久化任务＋状态查询，不让HTTP无限等待 |
| 前端重构引发回归 | 每完成2A一个小步就跑第一阶段E2E |
