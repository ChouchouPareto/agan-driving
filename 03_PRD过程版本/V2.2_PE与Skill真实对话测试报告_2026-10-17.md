# V2.2 PE 与内部 Skill 真实对话测试报告

测试日期：2026-10-17。代码基线：`dab81c2`，PE 版本：`pe-v1.3-human-confirm`。

## 结论

**真实模型可以响应，但有效连续对话尚未通过验收。** 普通聊天、明确题目和部分服务咨询能答；话题承接、专业事实约束、口诀和业务工具执行存在确定性缺口。上轮工程报告中的“邀请制试点候选”只证明基础流程测试通过，不能作为对话质量已经达标的依据。当前建议先修复本报告的阻断问题，再开放真实学员的自主使用；演示应由工作人员陪同观察。

本轮按要求只测试并记录结果，没有修改产品回答逻辑、生产数据库或线上部署。

## 测试方法与边界

- 使用本地 V2.2 后端，通过真实 HTTP API 路径及 SSE 答案流测试；TestClient 不等于模型 Mock，外部模型请求为真实调用。
- 对话/意图模型：`qwen3.6-flash`；种子题追问使用 `qwen3.7-plus`；激活题库补测调用 `text-embedding-v4`。
- 复制现有数据库到临时目录并新建测试学员；测试结束删除临时副本，没有向真实学员记录写入对话。
- 主测试：8 组连续会话、32 轮，覆盖全部 10 个已登记 skill。独立测试学校使用种子题与咨询知识，**该组不代表完整题库 RAG 质量**。
- 补测：使用现有激活题库所属学校的配置，新建临时测试学员，再测 5 轮题目、追问、口诀和话题切换。
- 测试状态关闭了应用限流，以验证语义而不是负载容量；未验证公网、手机 UI、生产模型配置、并发能力或法规最新性。
- 相关自动化回归 22 项均通过；其中存在 Mock 与固定路由断言，不能替代本次真实语义验收。

## 关键失败案例

| 测试位置 | 用户输入 | 实际结果 | 判定 |
| 主 #2–3 | 抱怨教练、说明考试没过 | 转成“明明做了还错”，随后问“科一没过，还是已经拿到证了” | 忽略具体处境，承接不自然 |
| 主 #7 | 别打开错题本，我想聊聊为什么总犯同一种错 | 返回打开错题本建议 | 否定意图识别失败；已不是自动跳转，但建议仍违背意愿 |
| 主 #13 | 你刚刚讲的那道题是什么？ | 新建题目检索，返回无可靠依据 | 题目与聊天上下文割裂 |
| 主 #15 | 杭州，C2，已经通过科目一，每周只能周末去 | OUT_OF_SCOPE，未携带本轮政策证据；回答给出与库内资料冲突的预约间隔 | 专业咨询不可接受 |
| 主 #16 | 你能保证我一个月拿证吗？ | 拒绝保证，但回复重新引用 C1 条件 | 没有稳定延续上一轮 C2 信息 |
| 主 #19 | 我的正确率和薄弱点是什么？ | “暂时看不到你具体的刷题数据” | 诚实但业务能力未接通 |
| 主 #21 | 帮我转人工，联系校长 | 声称没有权限，建议找 APP 客服 | 没返回已有校长入口，也没有创建工单 |

| 主 #27 | 报名要带身份证吗？不要记录我的个人信息 | 整体被当作敏感信息阻止 | 将讨论材料名称误判成发送个人数据 |

## PE 工程检查

已经具备：意图分类提示词、题目解释提示词、陪伴提示词、标准答案锁定、部分敏感数据和注入拦截、最近 8 条聊天记录、模型调用追踪。明确题目的教学解释与普通聊天采用不同输出方式。

尚未落实到执行的部分：

1. **规则优先级存在冲突。** “错题”等关键词在一般情绪和语义判断之前命中；否定规则只覆盖有限词组。`has_context` 将聊天记录和题目记录混用，导致情绪对话中的“为什么”也转入讲题。
2. **分类器不掌握完整会话。** 只接收当前文本和一个是否有上下文的布尔值。5 次分类请求超时后降为 OUT_OF_SCOPE，后续即使模型能聊天，也不会检索所需专业证据。
3. **聊天模型只读取 AgentTurn。** 标准题答案与导航记录未统一传入聊天历史，学员从讲题切换到口诀或聊天时，模型缺少刚才的完整题目与答案。
4. **自然语言档案没有可靠更新。** 用户说 C2、杭州、已过科一，并不会自动更新传给模型的结构化资料；API 请求的默认 C1/科一上下文仍可能与用户陈述冲突。
5. **提示词不是校验器。** 虽然写了无依据不猜、不能靠猜题，但后处理只检查少数禁用短语，没有验证口诀来自已审核列表，也没有验证数字与证据一致。
6. **存在未执行的提示词。** `FOLLOW_UP_REWRITE_PROMPT` 已定义，但实际追问改写只是把旧题干与新问题拼接。

## 内部 Skill 实际情况

当前 10 个 skill 主要是 Python 注册表中的契约与路由分组，并不是 10 个已经独立执行、验证完备的技能流程。`required_context`、`tools`、`completion`、`fallback` 字段目前没有通用执行器进行加载、调用或验收；普通 RESPOND 分支共享陪伴提示词，`skill_id` 主要用于记录。

| Skill | 本轮验证 |
|---|---|
| safety_guard | 显式注入、模拟手机号可拦截且不调用模型；身份证材料咨询误拦截 |
| practice_coach | 正向刷题可返回确认入口；否定错题意图失败 |
| theory_tutor | 明确原题有答案与依据；旧库向量检索失败，聊天追问误触发 |
| mnemonic_coach | 有注册与正则口诀库，但未限制模型只使用库内口诀；关键失败 |
| learning_diagnosis | 意图识别正确，未把进度统计传给模型 |
| school_service | 可以普通回复；school_profile/principal_ticket 只是声明，本分支不执行对应操作 |
| practical_companion | 有通用建议，缺 training_playbook 的实际调用；连接失败时泛化模板 |
| driving_advisor | 会检索 5 条咨询知识，但补充条件的下一轮可能漏检索；没有事实一致性验收 |
| product_guide | 能介绍部分能力，未读取 capability_catalog，遗漏/误述现有功能 |
| companion_chat | 真模型、有近 8 条聊天历史；能交流但容易预设用户情绪与重复二选一话术 |

## 数据库故障证据

只读检查确认：本地 Alembic revision 为 `b73d9012f5aa`，代码 head 为 `d4c9f3a7b812`。`knowledge_chunks` 表实际没有 `embedding` 字段，而 ORM 和 `_load_vector_index` 已要求读取它。直接只读调用得到：`no such column: knowledge_chunks.embedding`。

精确原题可以绕开向量读取，故原题成功不代表追问成功。迁移增加字段后还需要检查已有向量是否已回填，不能仅把 revision 升到 head 就认为检索恢复。未检查线上库，不能据本地结果断言线上同样故障。

## 修复优先级与复验门槛

1. 先处理旧库迁移、已有向量回填和非精确检索错误恢复；复验真实激活题库原题、改写、追问、无答案。
2. 统一聊天/题目历史，修复否定与话题切换，分类器携带必要上下文；本报告所有确定性路由失败需清零。
3. 将口诀、政策数字与证据做强约束；没有依据时不生成口诀或确定数字。
4. 给学习诊断、校长联系和产品引导接上真实数据/入口，验证“实际执行成功”，不只断言 skill_id 正确。
5. 对模型连接失败、分类超时和重试降级分别记录，确保用户已提供的信息在降级中仍被保留。
6. 用独立多轮集重复运行，并人工复核相关性、承接、证据、语气与动作。通过后再重新评定试点条件。
