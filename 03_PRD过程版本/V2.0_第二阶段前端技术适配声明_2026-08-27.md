## 1. 项目判断

| 项目 | 结论 |
|---|---|
| 产品类型 | 驾校交付给学员的 B2B2C 科目一教育 Agent |
| 主要用户 | 学员；第二阶段新增校长/值班教练 |
| 主要终端 | 学员侧移动 Web 优先；校长侧桌面 Web 优先并兼顾移动处理 |
| 项目状态 | 已有可运行项目，不是新建工程 |
| 已完成基线 | 邀请进入、文字问答、OCR 确认、可信回答、学员反馈、工单创建/查询 |
| 第二阶段目标 | 让异常问题从“创建工单”升级为“校长可领取、核查、回复，学员可查看并确认结束”的真实闭环 |

第二阶段核心闭环：

    学员提交给校长
      → 工单进入等待队列
      → 校长查看脱敏上下文
      → 校长领取并处理
      → 校长回复
      → 学员查看回复
      → 学员确认解决
      → 工单关闭并保留审计

第二阶段不建设知识发布平台、评测中心、学习进度页和提醒系统。

## 3. 当前前端基线

### 3.1 已具备

- Next.js 16.3.3、React 19.2.4、TypeScript strict；
- App Router 和同源 BFF；
- HttpOnly Cookie 学员会话；
- 统一 API Client、错误归一化和 Zod Schema；
- TanStack Query Provider；
- SSE 解析和任务状态映射；
- OCR 独立 Feature、URL 恢复和移动端交互；
- Loom 视觉 Token、Lucide 图标和减少动画支持；
- Vitest、MSW、Playwright；
- 桌面与移动端第一阶段 E2E。

### 3.2 第二阶段缺口

1. 没有校长/值班教练身份与独立会话；
2. 没有后台 App Shell、工单列表和工单详情；
3. 没有领取、回复、关闭和并发冲突接口；
4. 没有内部备注与学员可见回复的字段边界；
5. 学员工单只有状态卡，没有独立详情和回复时间线；
6. 没有队列 loading、empty、failed、permission_denied 的完整区分；
7. 没有 SLA、超时和 P0 风险的前端表现；
8. 没有工单状态变化后的缓存失效和跨页面同步；
9. 没有校长闭环的真实 E2E。

## 4. 技术选择

### 4.1 框架与版本

- 延续 Next.js 16.3.3、React 19.2.4、TypeScript strict；
- 不跨大版本升级；
- 按当前 Next.js 本地文档实现 App Router、Route Handler 和 Cookie；
- 不把整个后台变成单一巨大 Client Component。

### 4.2 样式与组件

- 保留现有全局语义 CSS 和 Loom Token；
- 新增校长工作台布局与业务组件；
- 暂不迁移 Tailwind，避免在工单闭环阶段扩大回归面；
- 暂不引入完整组件库；
- 如果出现带焦点约束的 Dialog/Drawer，再引入 Radix 对应单组件；
- Lucide 继续作为唯一图标库。

### 4.3 数据请求与状态

- 服务端工单数据使用 TanStack Query；
- ticketId、筛选、页码进入 URL；
- 回复草稿、抽屉开关等放组件局部状态；
- 不引入 Zustand；
- 后端是状态、权限和最终回复的唯一事实来源；
- 状态变更后通过 Query invalidation 更新列表、详情和学员端。

### 4.4 通信策略

- 列表、详情、领取、回复和关闭使用普通 HTTP；
- MVP 使用可见页面下的有节制轮询恢复工单状态；
- 页面不可见时暂停或降低轮询；
- 本阶段不引入 WebSocket；
- 学员问答 SSE 保持不变。

### 4.5 表单

- 校长回复使用受控表单＋Zod；
- 若加入内部备注、回复依据等动态字段，再评估 React Hook Form；
- 提交失败保留草稿；
- 领取、回复和关闭都带幂等键；
- 高风险关闭操作需要业务意义明确的确认。

### 4.6 测试

- Vitest：状态映射、Schema、权限和错误归一化；
- React Testing Library：队列状态、领取、回复、冲突和草稿保留；
- MSW：组件层接口模拟；
- Playwright：学员转人工 → 校长处理 → 学员确认的真实闭环；
- 人工浏览器：390、768、1280、1440px。

## 5. 身份与权限适配

### 5.1 会话

学员 Cookie 与校长 Cookie 必须区分，避免同一浏览器角色串线。

建议：

- 学员：student_session；
- 校长：staff_session；
- 管理端 BFF 只读取 staff_session；
- 后端依据 Staff 角色执行最终权限判断。

### 5.2 测试身份

校长真实账号来源尚未确认，第二阶段开发可采用配置化管理员邀请码或预置测试账号。界面必须标注测试环境，不能把测试身份设计成正式组织规则。

### 5.3 权限

| 角色 | 前端可见能力 | 后端强制能力 |
|---|---|---|
| 学员 | 查看自己的工单和用户可见回复、确认解决 | 只能访问本人 ticket |
| 值班校长/教练 | 查看授权驾校队列、领取、回复 | school_id 和角色校验 |
| 项目运营 | 只读查看必要状态 | 不得代替专业回复 |
| 知识管理员 | 本阶段无入口 | 2D 再开放 |

前端隐藏按钮不等于权限控制。403 必须显示独立 permission_denied 状态。

## 6. Agent 工单状态

### 6.1 后端到前端映射

| 后端状态 | 学员文案 | 校长端文案 | 前端统一状态 |
|---|---|---|---|
| SUBMITTED | 提交给校长 | 新提交 | queued |
| QUEUED | 校长在摸鱼 | 待领取 | queued |
| PROCESSING | 校长处理中 | 处理中 | running |
| REPLIED | 校长已回复 | 已回复，待学员确认 | waiting_user |
| CLOSED | 校长说好了 | 已完成 | succeeded |
| FAILED | 处理遇到问题 | 处理失败 | failed |
| 未知 | 状态待确认 | 状态待确认 | stale |

“校长在摸鱼”只用于学员端，同时显示正式说明；后台使用正式业务文案。

### 6.2 状态规则

- 领取只能从 QUEUED 进入 PROCESSING；
- 同一工单只允许一名处理人有效领取；
- 回复只能由当前处理人或授权角色提交；
- REPLIED 不等于 CLOSED；
- AI 不得自动关闭工单；
- 学员查看不是默认关闭，需明确确认解决或采用经确认的超时规则；
- 未知状态不映射为成功。

## 7. 页面与产物

### 7.1 学员端

- /tickets/[ticketId]：问题摘要、五段状态、正式 SLA 说明、校长回复、时间线、确认解决。

### 7.2 校长端

- /staff/enter：测试身份进入；
- /staff/tickets：队列、筛选、分页和风险提示；
- /staff/tickets/[ticketId]：上下文、OCR、AI 回答、依据、风险、领取、回复和审计摘要。

不使用 /admin 作为默认用户文案，但路由是否采用 /admin 或 /staff 可在接口冻结时统一；推荐 /staff，降低“系统管理员”与“专业处理人”混淆。

### 7.3 工单产物

工单不是通用媒体 Artifact。本阶段产物为：

- 校长对学员可见的专业回复；
- 引用的题库/法规依据摘要；
- 工单事件时间线；
- 处理状态和审计 ID。

内部备注和完整调试信息不得下发学员端。

## 8. 页面状态矩阵

| 页面/模块 | 初始 | 加载 | 空 | 运行 | 等待确认 | 成功 | 失败 | 恢复 |
|---|---|---|---|---|---|---|---|---|
| 学员工单详情 | 骨架 | 查询中 | 无工单 | 校长处理中 | 校长已回复 | 校长说好了 | 查询失败 | ticketId 重查 |
| 校长队列 | 默认筛选 | 列表加载 | 暂无待办 | 自动刷新 | — | 展示列表 | 加载失败 | 保留筛选重试 |
| 工单详情 | 未选择 | 详情加载 | 不存在 | 处理中 | 待填写回复 | 回复成功 | 越权/冲突/失败 | ticketId 重查 |
| 回复表单 | 空草稿 | 提交中 | — | — | 校验错误 | 已回复 | 保留草稿 | 查询状态后判断 |

loading、empty、failed、permission_denied、not_found 必须分开。

## 9. 接口依赖

第二阶段前端依赖后端新增：

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | /api/v1/staff/auth/invitations/verify | 校长测试身份进入 |
| GET | /api/v1/staff/me | 当前角色和驾校范围 |
| GET | /api/v1/staff/review-tickets | 队列、筛选、分页 |
| GET | /api/v1/staff/review-tickets/{id} | 脱敏详情和时间线 |
| POST | /api/v1/staff/review-tickets/{id}/claim | 幂等领取 |
| POST | /api/v1/staff/review-tickets/{id}/reply | 回复学员 |
| POST | /api/v1/review-tickets/{id}/acknowledge | 学员确认解决 |
| GET | /api/v1/review-tickets/{id} | 学员状态、回复和时间线 |

关闭接口是否单独开放待业务规则确认。默认优先由学员 acknowledge 触发 CLOSED，不允许校长在回复同时静默关闭。

## 10. 响应式适配

### 学员端

- 390px 可查看完整回复、时间线和确认按钮；
- 不使用横向表格；
- 主操作不被底部浏览器工具栏遮挡。

### 校长端

- 1280/1440px：232px 侧栏＋列表＋详情；
- 768px：列表与详情分路由或抽屉；
- 390px：卡片队列和独立详情，不强塞桌面三栏；
- 触控目标不小于 44×44px；
- 不出现无意横向滚动。

## 11. 无障碍与文案

- 队列筛选、领取、回复和确认均可键盘完成；
- 状态不只靠颜色；
- 新回复使用克制的 live region；
- 抽屉/Dialog 正确约束并返回焦点；
- 风险级别提供文字标签；
- 用户文案不出现 PROCESSING、requestId 等内部术语；
- requestId 和审计信息放在折叠详情或开发模式。

## 12. 安全与隐私

- staff_session 使用 HttpOnly、SameSite Cookie；
- BFF 与后端共同防止学员 Cookie 调用 staff API；
- 校长只能看到所属驾校或授权队列；
- 学员身份证、财务、缴费等字段不进入工单详情；
- 原图访问继续使用短时授权与所有权校验；
- 内部备注和审核信息不进入学员响应；
- 回复文本按纯文本渲染，不直接渲染不可信 HTML；
- 领取、回复和关闭均记录操作者、requestId 和幂等键；
- 403、404 不通过差异化敏感信息泄露对象存在性。

## 13. 可观测性与产品指标

前端至少携带或记录：

- requestId、ticketId、staffId 的安全标识；
- 页面、操作、状态、错误码；
- 领取、首次响应、回复和关闭时间；
- 并发冲突、重复提交和恢复次数；
- 应用版本。

业务指标：

- 人工转接率；
- 待领取时长；
- 首次响应时长；
- 回复完成时长；
- 学员确认解决率；
- 超 SLA 数；
- 重复打开和恢复成功率。

埋点失败不能阻断工单操作，不采集完整问题和回复正文。

## 14. 与手册默认方案的偏离

| 偏离 | 原因 | 影响 |
|---|---|---|
| 不引入 Tailwind | 现有项目已有语义 CSS 和 Loom Token | 使用现有样式体系增量建设 |
| 不引入 Zustand | URL、服务端状态和局部状态已能清晰分层 | 降低全局状态复杂度 |
| 暂不引入 React Hook Form | 回复表单首版字段少 | 字段增加后再评估 |
| 不立即生成 OpenAPI Client | 后端第二阶段契约仍需冻结 | 使用 Zod＋Feature API，稳定后生成 |
| 不使用 WebSocket | 状态变化频率不高，轮询足够 | 减少实时系统复杂度 |
| 不立即接 Sentry/分析平台 | 尚未确定正式部署与授权方案 | 保留 requestId 和错误边界，试点前补 |
| 不做通用 Artifact 模型 | 本阶段产物是结构化人工回复 | 避免过度抽象 |

## 15. 真正影响开发的待确认事项

1. 校长测试登录采用独立邀请码还是预设账号；
2. 同一驾校工单是全员可领取，还是按指定教练分配；
3. 工作时间、普通 SLA 和 P0 SLA；
4. 回复后由学员确认关闭，还是允许校长带理由关闭；
5. 是否允许内部备注；如允许，哪些角色可见；
6. 移动端校长工作台是否属于本阶段必须验收范围；
7. 校长是否能查看原始题目图片，还是只看 OCR 和脱敏缩略图。

以上保持配置化或待确认，不在开发中私自定为正式规则。

## 16. 当前结论

- 第二阶段前端范围限定为 2C 校长工单闭环；
- 延续当前 Next.js、BFF、Cookie、Zod、TanStack Query 和 Loom 设计体系；
- 新增校长身份、队列、详情、领取、回复及学员确认页面；
- 后端仍是状态、权限和最终结果的唯一事实来源；
- 2D 知识评测和 2E 学习证据不进入本阶段；
- 本声明通过审核前，不启动第二阶段开发。
