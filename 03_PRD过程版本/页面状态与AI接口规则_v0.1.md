# 页面、状态与AI接口规则 v0.1

## 1. MVP页面清单

### 学员Web端

| 页面 | 核心内容 | 主要状态 |
|---|---|---|
| 邀请进入页 | 邀请码、数据使用说明、进入服务 | 正常、邀请码无效、已失效、网络错误 |
| 首页/助教页 | 提问入口、拍照入口、提醒卡片、最近问题 | 首次使用、有历史、存在未读处理结果 |
| 对话页 | 问题、OCR校正、回答卡片、追问和反馈 | 识别中、检索中、生成中、完成、需补充、失败 |

## 2. 回答状态流转

```text
已提交
→ 识别中
→ 路由中
→ 题库匹配/RAG检索
→ 生成与机器检查
   ├─ 通过 → 已回答
   ├─ 信息不足 → 待学员补充
   ├─ 可重试失败 → 生成失败/允许重试
   └─ 存在风险 → 待复核
```

规则：

- 超时或失败不能展示残缺答案作为正式结论；
- OCR低置信度时先让学员校正，不直接高可信匹配；
- 题库标准答案和模型解释冲突时不展示模型解释，直接进入复核；
- 内容下线后，历史记录保留处理痕迹，但不继续展示为有效答案。

## 3. 异议工单状态

学员侧状态：

```text
提交给校长
→ 校长在摸鱼
→ 校长处理中
→ 校长已回复
→ 校长说好了
```

后台状态映射：

| 学员侧文案 | 后台状态 | 含义 |
|---|---|---|
| 提交给校长 | `SUBMITTED` | 工单创建成功 |
| 校长在摸鱼 | `QUEUED` | 等待机器复核或值班人员接单 |
| 校长处理中 | `PROCESSING` | 已接单，正在核查或修正 |
| 校长已回复 | `REPLIED` | 处理结论已回传，等待学员查看 |
| 校长说好了 | `CLOSED` | 学员已查看或工单完成关闭 |

需要学员补充信息或升级专业审核时，后台可记录子状态，但学员侧仍停留在“校长处理中”，并在详情中展示具体说明。

每次状态变化记录操作者、时间、理由、题库/法规版本和处理结果。普通异议工作时间内2小时响应；P0立即提醒项目负责人和专业审核人。学员侧只展示“不懂就问校长”及上述趣味状态，不暴露后台具体分派角色。

## 4. 学习记忆状态

知识点掌握状态采用轻量四态：

| 状态 | 进入条件 |
|---|---|
| 未判断 | 只有浏览或没有有效反馈 |
| 疑似薄弱 | 首次答错、表示没看懂或提出有效追问 |
| 薄弱 | 7天内同知识点连续2次错误 |
| 已改善 | 后续同知识点连续正确或明确确认理解，具体判定可由测试数据调优 |

提醒关闭只影响普通提醒展示，不删除错题和薄弱点记录；数据删除申请按隐私规则处理。

## 5. AI工作流输入

业务后端向AI编排层传递最小必要字段：

```json
{
  "request_id": "唯一请求ID",
  "student_context": {
    "anonymous_student_id": "匿名学员ID",
    "school_id": "驾校ID",
    "subject": "科目一",
    "license_type": "C1",
    "region": "适用地区",
    "rule_version": "规则版本",
    "weak_knowledge_tags": ["知识点标签"]
  },
  "question": {
    "input_type": "text|image",
    "raw_text": "学员输入或确认后的OCR文本",
    "image_reference": "短期有效的内部图片引用",
    "conversation_context": ["当前问题必要的有限上下文"]
  }
}
```

禁止传递与当前回答无关的身份证号、缴费、财务和完整联系方式。

## 6. AI工作流输出

```json
{
  "request_id": "唯一请求ID",
  "route": "standard_question|open_theory|out_of_scope",
  "status": "answered|need_clarification|needs_review|refused|failed",
  "answer": {
    "direct_answer": "直接答案",
    "short_reason": "一句话解释",
    "detail": "详细解释",
    "common_mistake": "易错点",
    "next_actions": ["understood", "explain_again", "report_issue", "similar_question"]
  },
  "evidence": [
    {
      "source_type": "question_bank|regulation|teaching_card",
      "source_id": "来源ID",
      "title": "来源标题",
      "version": "版本",
      "excerpt": "必要的依据摘要"
    }
  ],
  "quality": {
    "question_match_confidence": 0.0,
    "retrieval_confidence": 0.0,
    "answer_consistency_passed": true,
    "risk_codes": []
  },
  "trace": {
    "question_bank_version": "题库版本",
    "prompt_version": "Prompt版本",
    "model_id": "模型ID",
    "workflow_version": "工作流版本"
  }
}
```

前端只根据`status`展示对应状态，不自行推断模型置信度。置信度阈值和风险组合由后端/工作流统一配置并版本化。

## 7. 核心风险编码

| 编码 | 含义 | 默认处理 |
|---|---|---|
| NO_TRUSTED_MATCH | 无可信题库或知识命中 | 拒绝确定回答并进入“不懂就问校长”复核 |
| OCR_LOW_CONFIDENCE | OCR关键信息不完整 | 要求学员校正 |
| SOURCE_CONFLICT | 多来源结论冲突 | 转专业审核 |
| VERSION_UNCLEAR | 地区、车型或规则版本不明 | 补充询问或转审核 |
| ANSWER_EVIDENCE_CONFLICT | 回答与依据不一致 | 禁止展示并转复核 |
| USER_DISPUTE | 学员提出答案异议 | 创建“不懂就问校长”可追踪工单 |
| POLICY_RECENTLY_UPDATED | 涉及近期更新规则 | 转专业审核 |
| OUT_OF_SCOPE | 非科目一或不适合回答 | 说明范围，不自由发挥 |

## 8. 最低埋点

- 进入服务、邀请码验证结果；
- 发起文字/图片问题；
- OCR成功、校正和失败；
- 问题路由结果；
- 题库命中、RAG召回和无命中；
- 回答成功、失败、耗时和成本；
- 看懂、仍不懂、答案异议、相似题操作；
- 异议工单创建、接单、完成和超时；
- 提醒生成、展示、点击和关闭；
- 数据删除申请及完成。
