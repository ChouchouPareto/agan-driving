## 1. 本阶段目标

让学员提交的异常问题不再停留在“校长在摸鱼”的静态状态：校长能够进入真实队列、领取问题、查看必要上下文、提交专业回复；学员能够刷新或稍后返回查看回复并确认问题解决。

成功链路：

    学员答疑异常或主动提出异议
      → 创建同一问题的唯一工单
      → 校长队列出现该工单
      → 校长领取
      → 查看脱敏问题、OCR、AI回答、依据和风险
      → 提交学员可见回复
      → 学员在工单详情看到回复
      → 学员确认解决
      → 工单进入“校长说好了”

## 3. 用户与权限

### 3.1 学员

- 只能查看自己的工单；
- 可以查看用户可见时间线和校长回复；
- 可以确认“这个问题解决了”；
- 不能查看领取人内部信息、内部备注和其他学员工单。

### 3.2 值班校长/教练

- 只能查看授权驾校范围内工单；
- 可以领取未被领取的工单；
- 可以查看处理所需的脱敏上下文；
- 可以提交专业回复；
- 不得发布正式知识；
- 默认不能绕过学员确认直接关闭。

### 3.3 项目运营

- 如本阶段需要，仅提供只读队列；
- 不得以运营身份提交专业结论；
- 是否进入本阶段待确认，默认不做专门页面。

## 4. 用户流程

### 4.1 学员转人工

1. 学员点击“不懂就问校长”或“答案有问题”。
2. 前端带幂等键创建工单。
3. 重复操作返回同一 ticketId。
4. 页面展示“提交给校长/校长在摸鱼”和正式 SLA。
5. 学员可进入 /tickets/[ticketId]。
6. 刷新后按 ticketId 恢复真实状态。

### 4.2 校长进入队列

1. 校长通过测试身份入口登录。
2. 后端返回角色、驾校范围和会话。
3. 进入默认“待领取”队列。
4. 页面先显示 loading，成功且无记录后才显示 empty。
5. 校长可按状态、风险和等待时长筛选。
6. URL 保存筛选和页码。

### 4.3 领取与处理

1. 校长打开工单详情。
2. 页面展示问题、OCR、AI 回答、依据和转人工原因。
3. 校长点击“领取并开始处理”。
4. 前端提交幂等请求。
5. 若被他人先领取，展示冲突并刷新真实处理人和状态。
6. 领取成功进入 PROCESSING。

### 4.4 回复

1. 当前处理人填写学员可见回复。
2. 表单明确提示内容将直接展示给学员。
3. 校验非空、长度和必要依据。
4. 提交中禁止重复点击。
5. 失败保留草稿并显示 requestId。
6. 成功进入 REPLIED，队列和详情缓存失效。

### 4.5 学员确认

1. 学员重新打开或刷新工单详情。
2. 页面显示“校长已回复”、回复正文和依据。
3. 学员点击“这个问题解决了”。
4. 后端幂等进入 CLOSED。
5. 页面展示“校长说好了”。
6. 如果仍未解决，首版保留再次说明入口还是创建新工单，待产品确认；默认不自动关闭。

## 5. 页面状态矩阵

| 页面/模块 | 初始 | 加载 | 空 | 运行 | 等待确认 | 成功 | 失败 | 恢复 |
|---|---|---|---|---|---|---|---|---|
| /staff/enter | 登录表单 | 验证中 | — | — | — | 跳转队列 | 身份无效/网络错误 | 已登录自动跳转 |
| /staff/tickets | 默认筛选 | 骨架屏 | 暂无待办 | 后台刷新 | — | 工单列表 | 保留筛选重试 | URL 恢复 |
| 工单列表项 | 状态标签 | — | — | PROCESSING | REPLIED | CLOSED | stale | 刷新单项 |
| /staff/tickets/[id] | 页面骨架 | 详情加载 | — | 已领取处理 | 等待回复 | 回复成功 | 403/404/冲突/网络 | ticketId 重查 |
| 领取按钮 | 可领取 | submitting | — | 已领取 | — | 进入处理中 | 并发冲突 | 查询详情 |
| 回复表单 | 空草稿 | submitting | — | 编辑中 | 字段错误 | 已回复 | 保留草稿 | 查询后判断是否已提交 |
| /tickets/[id] | 状态骨架 | 查询中 | — | 校长处理中 | 校长已回复 | 校长说好了 | 不存在/失败 | ticketId 重查 |
| 学员确认 | 未展示 | submitting | — | — | 等待学员 | 已关闭 | 保留回复 | 查询真实状态 |

规则：

- loading 期间不显示“暂无工单”；
- 403、404、failed 分开；
- 未知后端状态进入 stale；
- 网络中断不能把任务标为失败或关闭；
- 前端动画和计时不能改变业务状态。

## 10. 接口契约

### 10.1 校长身份验证

POST /api/v1/staff/auth/invitations/verify

输入：

    {
      "code": "测试邀请码"
    }

成功：

    {
      "staff_id": "uuid",
      "display_name": "值班校长",
      "role": "reviewer",
      "school_id": "pilot-school"
    }

BFF 设置 staff_session，浏览器不接收 Token。

错误：

- INVALID_STAFF_INVITATION；
- STAFF_DISABLED；
- RATE_LIMITED。

### 10.2 工单列表

GET /api/v1/staff/review-tickets?status=QUEUED&risk=P0&page=1

成功：

    {
      "items": [],
      "page": 1,
      "page_size": 20,
      "total": 0,
      "request_id": "uuid"
    }

规则：

- 支持状态、风险、是否超时和分页；
- 默认按风险等级、超时、创建时间排序；
- 未知状态保留并安全展示；
- 普通轮询失败保留上一份列表，并提示状态可能过期。

### 10.3 工单详情

GET /api/v1/staff/review-tickets/{ticketId}

返回：

- 工单摘要；
- 脱敏问题；
- OCR 字段和受权缩略图；
- AI 答案与依据；
- 风险原因；
- 用户可见消息；
- 事件时间线；
- 当前用户 permissions；
- version 和 requestId。

### 10.4 领取

POST /api/v1/staff/review-tickets/{ticketId}/claim

请求头：

- Idempotency-Key；
- If-Match 或 body.version。

成功进入 PROCESSING。

错误：

- TICKET_ALREADY_CLAIMED；
- VERSION_CONFLICT；
- PERMISSION_DENIED；
- TICKET_NOT_CLAIMABLE。

发生冲突时前端重新拉取详情，不乐观覆盖真实处理人。

### 10.5 回复

POST /api/v1/staff/review-tickets/{ticketId}/reply

输入：

    {
      "version": 3,
      "message": "面向学员的专业回复",
      "evidence_ids": []
    }

要求：

- 幂等键；
- message 长度限制；
- 回复人与处理人权限；
- 返回最新 TicketDetail；
- 不接收 HTML；
- 不同时自动关闭。

### 10.6 学员工单

GET /api/v1/review-tickets/{ticketId}

只返回：

- 学员可见状态和文案；
- 正式 SLA 说明；
- 学员可见时间线；
- 校长公开回复；
- 可以执行的 next_actions。

不得返回处理人内部信息、内部备注和完整审计。

### 10.7 学员确认

POST /api/v1/review-tickets/{ticketId}/acknowledge

输入：

    {
      "resolved": true
    }

要求：

- 幂等；
- 只有工单本人；
- 默认只允许 REPLIED → CLOSED；
- 返回最终状态和时间线。

## 11. BFF 与 Cookie

- /api/backend 保持学员 Cookie；
- 新增 /api/staff-backend 或按路径选择 staff_session；
- 浏览器不读取 Bearer Token；
- BFF 透传 Idempotency-Key、requestId 和必要条件版本；
- 响应统一 no-store；
- staff 登录接口只把安全身份字段返回浏览器；
- Cookie 在生产环境使用 Secure；
- 退出时只清理对应角色 Cookie。

选择独立 staff BFF 路径，避免同一代理根据页面状态猜角色。

## 12. TanStack Query 策略

### 队列

- queryKey 包含 status、risk、overdue、page；
- 页面可见时 10–15 秒轮询作为待确认默认值；
- 页面隐藏时停止；
- 请求失败保留旧数据并标记 stale；
- 筛选变化取消旧请求。

### 详情

- ticketId 作为 queryKey；
- PROCESSING/REPLIED 可适度轮询；
- CLOSED 停止轮询；
- 领取/回复成功后更新详情并使列表失效；
- 冲突后强制重新获取。

### 学员详情

- QUEUED/PROCESSING 时轮询；
- REPLIED/CLOSED 停止或显著降低；
- 页面重新聚焦时重新验证。

轮询间隔在真实 SLA 和负载确认后配置化。

## 13. 表单与重复提交

### 回复表单

- 必填；
- 最小和最大长度由接口契约确定；
- 显示“该内容将直接展示给学员”；
- 提交失败保留输入；
- 成功后清空草稿；
- 切换工单且有未提交内容时提示；
- 不把回复正文写入 Local Storage。

### 幂等

- claim、reply、acknowledge 各自生成独立 Idempotency-Key；
- 超时后先查询工单状态；
- 已完成的相同操作不重复提交；
- 用户快速双击只发送一次。

## 14. UI 与交互

### 14.1 视觉

- 继续采用浅灰画布、白色卡片、紫色主行动；
- 风险色只用于标签和提示，不大面积铺色；
- P0 红色、P1 橙色、普通风险中性色；
- 细边框、轻层级、紧凑圆角；
- 后台密度高于学员端，但正文保持可读。

### 14.2 队列

每个列表项显示：

- 状态；
- 风险等级；
- 问题摘要；
- 等待时长/SLA；
- 是否已领取；
- 更新时间。

不显示：

- 身份证、手机号等敏感字段；
- 模型内部推理；
- 完整系统 Prompt。

### 14.3 详情

信息顺序：

1. 风险和当前状态；
2. 学员问题与 OCR；
3. AI 回答和证据；
4. 转人工原因；
5. 处理操作；
6. 时间线与调试详情。

普通处理者不需要先看到原始 JSON。

## 15. 错误与恢复

| 场景 | 页面处理 |
|---|---|
| 队列加载失败 | 保留筛选；有旧数据则标 stale；允许重试 |
| 工单不存在 | not_found 页面，不跳回假空列表 |
| 无权限 | permission_denied，不泄露详情 |
| 被他人领取 | 提示处理人已变化并刷新 |
| 回复超时 | 先查详情；若已回复则不重发 |
| 网络中断 | 显示“状态可能仍在变化”，恢复后查询 |
| 未知状态 | stale 提示和安全禁用高风险操作 |
| 学员查看过期图片 | 保留 OCR 文字和工单内容，不显示破图 |
| 会话过期 | 返回对应角色登录，保留安全 returnTo |

## 16. 安全与隐私验收

- 学员 Cookie 不能访问 staff API；
- staff Cookie 不能越权访问其他驾校；
- 修改 URL 不能读取其他工单；
- 内部字段不会出现在学员接口；
- 回复中危险 HTML 按文本显示；
- requestId 可查但不显示密钥；
- 图片仍通过受权端点访问；
- 所有写操作有后端权限、幂等和审计；
- 403 与 404 文案不泄露敏感对象存在性。

### 17.3 Playwright

## 18. 浏览器人工验收

### 学员

1. 打开测试入口并使用通过私密渠道取得的测试邀请码。
2. 创建一个需转人工的问题。
3. 点击“不懂就问校长”。
4. 打开工单详情。
5. 确认状态和 SLA 清楚。

### 校长

1. 打开校长测试入口。
2. 使用待确认的测试凭证。
3. 在待领取队列找到该问题。
4. 领取并输入回复。
5. 刷新页面，确认回复仍存在。

### 返回学员

1. 刷新工单详情。
2. 查看校长公开回复。
3. 点击“这个问题解决了”。
4. 确认最终状态“校长说好了”。

同时检查 Console、Network、重复请求、错误状态和响应式。

## 19. 验收标准

### Given / When / Then

#### 队列

- Given 学员已创建 QUEUED 工单；
- When 授权校长打开待领取队列；
- Then 真实接口返回该工单，loading 与 empty 不混淆。

#### 领取

- Given 工单尚未被领取；
- When 校长点击领取；
- Then 工单进入 PROCESSING，重复点击不产生重复事件。

#### 并发

- Given 两名校长同时查看同一工单；
- When 两人尝试领取；
- Then 只有一人成功，另一人看到冲突后的真实状态。

#### 回复

- Given 当前校长拥有处理权限；
- When 提交合法回复；
- Then 工单进入 REPLIED，学员可以看到公开回复，内部信息不泄露。

#### 关闭

- Given 学员已看到回复；
- When 学员确认问题解决；
- Then 工单进入 CLOSED，并显示“校长说好了”。

#### 恢复

- Given 工单处于任一有效状态；
- When 用户刷新、返回或短暂断网；
- Then 页面根据 ticketId 恢复后端真实状态，不重复写操作。

## 21. 风险与降级

| 风险 | 降级方案 |
|---|---|
| 校长账号规则未冻结 | 使用明确标注的测试邀请码，正式方案配置化 |
| SLA 未冻结 | 显示“服务时段待确认”，不伪造正式承诺 |
| 并发领取后端未完成 | 不开放领取按钮，不用前端锁冒充后端并发控制 |
| 原图已过期 | 展示 OCR、问题和审计摘要 |
| 移动后台工期不足 | 保证查看和回复最小闭环，复杂筛选只在桌面 |
| 回复关闭规则未确认 | 保持 REPLIED，必须由学员确认 |
| 后端接口滞后 | MSW 只推进组件，不宣布真实闭环完成 |
