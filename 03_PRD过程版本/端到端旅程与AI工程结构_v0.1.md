# 端到端旅程与AI工程结构 v0.1

## 一句话结论

学员通过驾校交付的入口提问，系统先识别问题类型，再由确定性题库或RAG提供事实，Prompt工程约束大模型完成解释，评测工程检查答案，异常才进入真人教练处理，最终将结果沉淀到题库、知识库和ERP/SaaS。

## 一、学员服务旅程

```text
驾校/教练邀请学员
        ↓
学员进入Web或未来的小程序入口
        ↓
系统识别学员、驾校和当前科目
        ↓
学员输入题目或自由咨询
        ↓
AI返回答案、通俗解析和知识依据
        ↓
学员继续追问或反馈是否解决
        ↓
正常问题结束；异常问题提醒人工/教练
        ↓
教练处理后结果回传给学员并沉淀
```

## 二、系统内部处理链路

```text
1. 接入层
   Web / 小程序 / ERP内嵌入口
        ↓
2. 身份与上下文层
   学员ID、所属驾校、驾照类型、当前科目、地区/规则版本
        ↓
3. 意图与路由层
   标准题 / 开放理论咨询 / 科二科三技巧咨询 / 非驾考问题
        ↓
4. 事实获取层
   ├─ 标准题：题库精确/模糊匹配
   ├─ 理论咨询：RAG检索法规与知识库
   └─ 技巧咨询：教练审核技巧卡与操作理论
        ↓
5. 生成与解释层
   大模型根据Prompt生成答案、解释、依据和风险提示
        ↓
6. 机器评测层
   标准答案比对、引用一致性、格式、冲突与置信度检查
        ↓
7. 决策层
   ├─ 正常：直接展示
   └─ 异常：提示不确定并进入人工/教练队列
        ↓
8. 反馈与沉淀层
   学员反馈、教练修正、错误归因、回归评测、结果写回ERP/SaaS
```

## 三、四条核心工程线

### 1. 题库与规则工程

这是科一、科四正确性的第一基础，不属于RAG的附属工作。

主要内容：

- 题目、选项、标准答案和解析结构化；
- 车型、地区、科目和规则版本标记；
- 重复题、相似题与变体题归一；
- 题库更新、版本变更和失效管理；
- 精确匹配与模糊匹配；
- 标准答案回归测试。

### 2. RAG工程

RAG主要解决开放理论问题和题目背后的法规解释。

主要内容：

- 选择权威知识来源；
- 文档清洗、分块和元数据；
- Embedding与向量索引；
- 关键词＋向量混合检索；
- Rerank重排；
- 车型、地区、版本过滤；
- 引用依据返回；
- 召回率、命中率和无答案测试；
- 知识更新与旧版本下线。

### 3. PE工程（Prompt Engineering）

PE负责让模型在拿到正确事实后，按照产品规则解释，而不是负责创造标准答案。

主要内容：

- System Prompt与角色边界；
- 问题分类Prompt；
- 标准题解释Prompt；
- 开放知识问答Prompt；
- 科二科三咨询澄清Prompt；
- Reviewer Prompt；
- 固定输出结构；
- 无依据拒答和异常提醒；
- Prompt版本管理与A/B测试；
- 防止模型覆盖题库标准答案。

### 4. 评测与审核工程

评测工程决定“回答正确”能否成为可验收指标。

主要内容：

- 标准题评测集；
- 口语化、信息缺失和歧义问题；
- 新规、冲突和无答案样本；
- 自动答案比对；
- RAG召回和引用一致性评测；
- 第二模型Reviewer辅助筛查；
- 异常进入人工/教练审核；
- 错误归因到题库、检索、Prompt、模型或产品规则；
- 修正后执行回归评测。

## 四、配套工程

### 产品与前端工程

- Web学员端；
- 教练异常审核端；
- 对话、依据、反馈和状态交互；
- 空状态、错误状态和等待状态。

### 后端与集成工程

- 用户、会话和权限；
- AI服务API；
- ERP/SaaS适配；
- Webhook预警与结果写回；
- 日志、成本、限流和重试。

### 数据与隐私工程

- 最小学员上下文；
- 数据授权；
- 学员、驾校与知识空间隔离；
- 敏感信息不进入Prompt；
- 数据保留和删除规则。

## 五、MVP最小团队能力

不一定需要每条工程线配置一个独立岗位，但需要明确有人承担：

| 能力 | MVP责任 |
|---|---|
| 产品 | 定义范围、流程、预警和验收 |
| 驾考专家/教练 | 审核题库、解析和异常答案 |
| AI应用工程 | Dify/Workflow、模型、Prompt和接口 |
| RAG/数据工程 | 知识清洗、索引、检索、重排和评测 |
| Web/后端工程 | 学员端、审核端、会话、日志和API |
| 测试/评测 | 评测集、机器评分、人工复核和回归 |

早期同一个人可以承担多项职责，但题库专业审核不能完全由模型代替。

## 六、MVP实现顺序

```text
先建立可信题库与评测集
        ↓
完成题目识别和确定性答案匹配
        ↓
完成RAG检索和知识引用
        ↓
通过PE工程约束回答格式和边界
        ↓
建立机器评测与异常预警
        ↓
接入Web学员端和教练审核端
        ↓
用真实学员测试并回归优化
        ↓
再考虑ERP/SaaS和小程序接入
```

## 七、关键原则

1. 标准答案来自题库，不来自模型猜测。
2. RAG负责找到正确依据，不自动等于回答正确。
3. Prompt负责约束解释，不替代题库和检索质量。
4. Reviewer模型只能辅助筛查，不能替代专业审核。
5. 异常预警必须可追踪、可处理、可回写。
6. Web只是首个入口，AI服务通过API保持独立。
