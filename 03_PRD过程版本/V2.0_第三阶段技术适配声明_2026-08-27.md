## 0. 结论

第三阶段不建设完整的人工知识审核平台，而是先完成科目一标准题库的可信 RAG 闭环：

```text
可信题库准入
→ 结构化导入
→ 机器校验
→ 精确/关键词/向量多路召回
→ Rerank
→ 标准答案一致性阻断
→ 带来源和版本的教学解释
→ 异常进入人工处理
```

本阶段坚持“题库决定标准答案，模型只负责解释”。可信来源题库通过机器校验和评测门禁后可生效，不要求逐题人工审核；来源不明、字段缺失、答案冲突、版本冲突和线上争议必须进入异常队列，不能进入生效版本，也不能由模型猜测。

## 1. 产品形态判断

- 产品形态：B2B2C 科目一教育 Agent，自建 Web 为 MVP 入口。
- 当前能力：文字/图片可信输入、OCR 人工确认、基础问答、校长工单闭环已经验收。
- 本阶段核心对象：标准题、标准答案、解析、知识点、来源、适用范围、题库版本、检索证据、评测样本。
- 本阶段目标：让线上回答从“基础模型回答”升级为“可追溯题库证据驱动回答”。
- 本阶段不是：刷题系统、通用文档问答平台、完整知识 CMS、法规研究平台或学习进度页面。

## 2. 已确认的产品规则

1. MVP 聚焦科目一。
2. 第一批资料由驾校既定供应商后续提供；开发期允许使用自行整理的小规模测试题库。
3. 标准题不设置逐题审核人。
4. 可信来源题库机器校验通过后可以生效。
5. 机器无法判定的异常才进入人工处理。
6. 模型不得修改标准答案。
7. 无可靠证据、证据冲突、版本不明或范围不匹配时拒答或转“不懂就问校长”。
8. 第一版只支持受控脚本导入 JSON/CSV，不建设用户自助批量导入页面。
9. 题库必须整批版本化，并支持停用和回退。
10. 发布前必须运行固定评测；P0 错误阻断版本生效。

## 3. 采用的默认方案

### 3.1 延续既有架构

| 层级 | 方案 |
|---|---|
| 学员端 | Next.js 16.3.3、React 19、TypeScript strict |
| BFF | Next.js Route Handler、HttpOnly Cookie |
| 后端 | FastAPI、Pydantic、SQLAlchemy、Alembic |
| 当前主数据 | SQLite，继续作为本地开发的业务事实源 |
| 模型调用 | 后端集中封装，密钥只存 `.env` 或部署 Secret |
| 测试 | pytest、Vitest、Playwright，阶段验收连接真实 FastAPI 与真实模型 |

不为接入 RAG 重写已经验收的 OCR、问答和工单模块。

### 3.2 本地 MVP 的 RAG 方案

| 能力 | 推荐实现 |
|---|---|
| 标准题精确匹配 | 规范化题干指纹 + 选项指纹 + 业务范围过滤 |
| 关键词召回 | SQLite FTS5；不可用环境降级为受控关键词匹配 |
| 向量召回 | Chroma PersistentClient，本地持久化 |
| Embedding | 阿里云百炼 `text-embedding-v4`，固定 1024 维 |
| Rerank | 阿里云百炼 `qwen3-rerank` |
| 融合 | 多路候选去重后使用 RRF 初排，再交给 Rerank 精排 |
| 生成 | 沿用现有主模型配置；标准答案作为不可变输入 |
| 事实源 | SQLite 保存题库、版本、校验、证据和评测；Chroma 只保存检索副本 |

选择 Chroma PersistentClient 是因为当前仍是本地 MVP、单进程写入和小规模试点，符合通用技术手册默认方案。Chroma 不是题库事实源，损坏或删除后必须能从 SQLite 重新构建。

### 3.3 试点/生产迁移路径

达到以下任一条件时，迁移 PostgreSQL + pgvector：

- 多进程或多实例需要并发写向量索引；
- 进入正式试点并要求统一备份、事务和高可用；
- 题库版本、过滤和统计查询明显超出本地方案边界；
- Chroma 本地目录成为部署或运维瓶颈。

生产目标方案：PostgreSQL 保存业务主数据、全文索引与向量，pgvector 提供精确/近似向量检索；混合召回可采用 PostgreSQL 全文检索 + pgvector + RRF/交叉编码器。迁移前必须单独输出数据迁移、回滚和兼容方案。

## 4. 触发的按需模块

### 4.1 知识版本

新增 `KnowledgeSource`、`KnowledgeVersion`、`StandardQuestion`、`KnowledgeChunk`。版本是不可变快照；新导入不覆盖旧版本。

### 4.2 导入任务

导入、机器校验、Embedding 和索引构建属于可恢复任务。任务持久化状态至少包含：`QUEUED / VALIDATING / EMBEDDING / INDEXING / READY / FAILED / BLOCKED`。

### 4.3 检索服务

RAG 调用集中在后端服务层，API 路由不得直接拼接向量请求或 Prompt。检索必须返回证据 ID、来源、题库版本、适用范围、各阶段分数和阻断原因。

### 4.4 自动质量评估

新增固定评测集与评测运行记录，至少检查：

- 标准题 Top-1 命中；
- 标准答案一致性；
- 引用证据存在且版本有效；
- 地区、车型和版本过滤正确；
- 无证据时安全拒答；
- P0 错误为零。

### 4.5 异常处理

异常不自动修正原始题库。第一版提供异常记录和只读/处置入口，支持：确认停用、重新导入、标记供应商待核实。人工处置必须审计。

## 5. 偏离或暂缓的默认方案

### 5.1 暂不直接迁移 PostgreSQL + pgvector

原因：当前本地 SQLite 数据、Alembic 和测试链路已经稳定；立即迁移会同时引入数据库运维、数据迁移和回归风险，且不是验证 RAG 产品价值的必要条件。

影响：本地 Chroma 不支持多个进程共享路径并发写；本阶段索引写入限定为单 Worker，读取可并发。生产前必须迁移或改用服务模式。

### 5.2 不使用百炼托管知识库作为唯一事实源

原因：标准题需要严格的答案不变量、整批版本、机器校验、回退、范围过滤和完整审计。托管知识库可作为后续对照实验，但本阶段由业务数据库掌握事实和版本。

### 5.3 不引入 LangChain/LlamaIndex

当前流程固定且工具数量有限。直接封装 Embedding、检索、融合和 Rerank 更容易测试、审计与阻断，也避免为框架完整性增加依赖。

### 5.4 暂不建设完整知识 CMS

本阶段只做版本、导入结果、异常和评测的最小管理入口；不做富文本编辑、多人审批、自由切片编辑和供应商门户。

### 5.5 暂不做图片向量检索

图片题先通过 OCR 形成结构化文本后进入检索。原图只作为题目资产和人工核查依据，不接入多模态 Embedding。

## 6. 强制底线检查

### 6.1 数据与版本

- SQLite 是本地事实源，Chroma 是可重建索引。
- 任何线上证据必须绑定 `knowledge_version_id`。
- 已生效版本不可原地修改。
- 新版本生效与旧版本停用必须在事务和审计中完成。
- 回退不能删除历史版本。

### 6.2 答案安全

- 精确命中标准题时，答案只能来自 `standard_answer`。
- 模型生成内容不得覆盖或改变标准结论。
- 候选之间答案冲突必须阻断。
- Rerank 分数是单次请求内的相对分数，不作为跨请求绝对置信度。
- 学员端不显示误导性的置信度百分比。

### 6.3 输入与导入安全

- 导入文件只允许受控本地路径或管理员接口。
- 校验扩展名、MIME、编码、行数、单元长度和总大小。
- CSV 公式注入字符在导出/预览时转义。
- 原始供应商文件保留哈希，不允许路径遍历。
- 题目正文不得包含身份证、缴费或其他无关敏感数据。

### 6.4 模型与密钥

- `DASHSCOPE_API_KEY` 只在后端读取。
- Embedding/Rerank 请求不包含学生身份和无关会话。
- 日志不记录完整题库、密钥或原始敏感内容。
- 记录供应商 requestId、耗时、Token 和安全错误码。

### 6.5 可恢复性

- 导入任务、Embedding 任务和评测运行可查询、重试、断点恢复。
- 重复导入使用内容哈希与幂等键去重。
- 向量索引可从指定知识版本全量重建。
- 模型不可用时保留精确匹配和安全拒答能力。

## 7. 技术事实与依据

- 百炼 `text-embedding-v4` 支持自定义 64–2048 维；本项目固定 1024 维，避免索引维度漂移。
- 百炼 `qwen3-rerank` 适用于文本检索/RAG；其相关分数仅在当前请求候选内比较。
- Chroma PersistentClient 适合本地持久化，但不是多进程并发写方案；Embedding 模型和维度变更必须创建新 collection 并重建索引。
- pgvector 支持精确/近似检索、HNSW/IVFFlat、过滤，并明确建议与 PostgreSQL 全文检索组合形成混合搜索。

## 9. 默认决策记录

若审核时未提出异议，第三阶段按以下默认值编写和开发：

- 测试资料：仓库内受控 JSON fixture，不含版权受限真实题库。
- 准驾车型：C1。
- 地区：全国。
- Embedding：`text-embedding-v4`，1024 维。
- Rerank：`qwen3-rerank`。
- 本地向量库：Chroma PersistentClient，单 Worker 写入。
- 候选规模：精确匹配优先；关键词 Top 20、向量 Top 20，去重后最多 30 条进入 Rerank，最终返回最多 5 条证据。
- 低质量处理：不生成确定答案，提供“不懂就问校长”。
- 生效门禁：P0 = 0；固定标准题正确率必须为 100%；其他阈值先记录基线，再由试点评测确认。
