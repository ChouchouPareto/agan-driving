## 2. 文档分类

- 正式 PRD：项目根目录，只保存可确认、可验收的产品版本。
- 过程文档：`03_PRD过程版本/`，保存技术适配声明、阶段开发文档、评审结论和上线报告。
- 需求沟通：`01_需求沟通记录/`，保存尚未进入正式版本的讨论、假设与待确认事项。
- 项目资料：`00_项目原始资料/`，保存竞品、视觉参考和外部输入材料。

## 3. 版本更新规则

每次产品更新至少记录以下内容：

1. 用户问题与版本目标。
2. 新增、调整、删除的产品能力。
3. 当前是“已完成、测试中、规划中”中的哪一种状态。
4. 对页面、数据、RAG、模型、权限、安全和运营的影响。
5. 验收结果、已知限制和下一步。
6. 对应 Git 分支、提交或发布版本。

禁止把原型、规划和已上线能力写在同一个状态中；没有真实素材或后端能力时，必须标记为“框架已完成”或“规划中”。
