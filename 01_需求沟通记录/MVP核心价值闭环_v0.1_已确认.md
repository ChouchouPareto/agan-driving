# MVP核心价值闭环 v0.1（已确认）

## 确认结论

2026-08-26，创作者确认MVP采用以下产品组合：

> 科目一智能答疑 + 轻量学员记忆 + 有限主动提醒 + 真人异常兜底 + 基础驾校效果看板。

用户侧异常兜底服务统一命名为“**不懂就问校长**”。后台仍按异常审核工单执行，并可由校长、值班教练或项目运营按排班承接。

用户侧状态文案确认为：“提交给校长 → 校长在摸鱼 → 校长处理中 → 校长已回复 → 校长说好了”。

项目不再只以“完成一次正确答题”为终点，而是形成“答疑—理解—记忆—提醒—效果证明”的体验与商业闭环。

## 双边价值

### 学员侧

- 在遇到不懂、易错和反复混淆的问题时快速获得帮助；
- 获得标准答案、通俗解释、错误原因和易错点，而不只是答案本身；
- 系统保留必要的历史问题、错题和薄弱知识点；
- 根据学习行为提供有限、事件触发式提醒；
- 异常或争议问题由真人教练兜底；
- 逐步形成“回答准确、解释易懂、系统了解我、驾校有人负责”的体验。

### 驾校侧

- AI承接高频、重复的科目一咨询；
- 教练集中处理异常、争议和高价值问题；
- 通过基础效果看板了解学员使用、AI解决效果和薄弱知识分布；
- 以学员满意度、服务效率和可见效果支撑续费与增购判断。

## MVP能力边界

### 本期纳入

1. 科目一文字答疑；
2. 标准答案、通俗解析、依据和易错点；
3. 历史问答、错题与薄弱知识点的轻量记录；
4. 连续同类错误、薄弱点小结、临考复习建议等有限提醒；
5. 无匹配、低置信度、知识冲突、版本异常及学员质疑的真人兜底；
6. 驾校基础效果看板。

### 本期不纳入

1. 完整刷题系统；
2. 复杂个性化学习计划；
3. 高频营销式或全渠道消息推送；
4. 完整ERP、教务或驾校经营管理系统；
5. 科目二、科目三和科目四的完整服务。

## 核心闭环

```text
驾校交付服务
→ 学员遇到问题并提问
→ 题库/RAG提供可信事实
→ AI生成准确、易懂的解释
→ 系统记录错题和薄弱点
→ 在关键时机提供有限提醒
→ 异常问题由教练兜底
→ 学员获得进步与被服务感
→ 驾校看见服务效果和效率价值
→ 形成口碑、续费与增购依据
```

## MVP基础指标方向

具体公式和目标值留待指标评审确认。

### 学员体验

- 回答正确率；
- 首次问题解决率；
- 学员反馈满意度；
- 重复使用率；
- 薄弱知识点改善情况。

### 服务效率

- AI独立解决率；
- 真人介入率；
- 异常问题平均响应时间；
- 单学员咨询服务成本。

### 驾校价值

- 使用学员数及活跃度；
- 高频问题与薄弱知识分布；
- 教练重复咨询量变化；
- 试点驾校续费或增购意愿。

## 题库来源决策（2026-08-26已确认并补充）

项目已有明确的驾校供应商，专业资料将在后续补充。MVP采用分阶段路线：在供应商资料到位前，由项目方自行整理小规模科目一种子题库用于技术和体验验证；资料到位后，完成导入、去重、版本核验和专业审核，并逐步将其升级为正式生产知识资产。

执行边界：

- 官方现行法规和标准作为事实依据；
- GitHub、公开网络题目和学习资料只作为整理线索与测试候选；
- 来源、版本或版权状态不清晰的内容不得直接标记为正式题目；
- 供应商资料也不默认直接上线，需确认授权范围、更新时间、地区/车型适用范围和完整性；
- 每道正式题至少记录来源、适用车型/地区、规则版本、审核人和审核状态；
- 未审核、存在冲突或过期的内容不得用于确定性返回标准答案；
- MVP试点应控制题库范围，优先覆盖真实学员的高频问题，而非一开始追求全量题库。

供应商资料到位前的种子题库用于验证系统，不代表最终商业题库；数据结构从第一版开始即需支持批量导入、来源标识、版本替换、差异比对和回滚。
